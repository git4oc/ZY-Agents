## 与架构文档的一处实质差异

`00` 撰写时假设内核是 **0.1.6-alpha.1**，其所有适配器代码可对照。
**本次决策锁定 0.2.0-rc.1，跨了一个大版本，没有现成适配可参照。**

这直接影响施工：

- 内核侧的扩展点需要**重新实测**，不能从任何旧版适配器代码直接推断；

- 实测结论见 `docs/03-kernel-contract.md` 第 7 节。

## 命名与标识

产品名 **`ZY-Agents`**，定名日 **`2026-09-29`**，替代此前零代码阶段的占位名 `ap-platform`。

> **`ZY` 取自项目代号（`ZY-Agents`）**——两字母缩写为项目命名约定。版权信息：`Copyright 2026 ZY-Agents Contributors`。这是**厂商标识**（不可变、进协议）；与之相对的是**客户品牌**（每部署可配，见 `00` §12）。

命名派生为**五种形态，用途互斥、不可混用**：

| 形态 | 取值 | 用途 |
|---|---|---|
| 展示名（完整） | `ZY-Agents` | 文档标题、产品对外表述、UI |
| 简写（对外） | `ZY` | 口头与书面简称、UI 短标签 |
| 标识符形态 | `zy` | 契约命名空间、kernel preset id、token `aud`、宿主事件类型、CLI 命令名、状态目录 |
| 路径形态 | `zy-agents` | 仓库目录名、容器镜像名前缀、JWT issuer、Python 发行包名 |
| 环境形态 | `zy_agents` | MongoDB 库名、下划线环境变量 |

> **为什么分五种形态**：判据是「给人读」还是「给机器唯一」。给人读的（目录、镜像名、JWT issuer、库名）用完整派生的 `zy-agents` / `zy_agents`；给机器唯一的（契约命名空间、preset id、`aud`、事件类型、CLI、状态目录）用简写 `zy`——契约命名空间必须**单段无连字符**，`zy.dsh-host.v1` 才能与参照项目的三段式命名空间（`<厂商>.dsh-host.v1`）保持同构。混用会在 CI 断言与锁文件里产生歧义。

### 命名依据

定名时核对过的四条硬条件：

1. **不与参照实现的前缀视觉混淆** —— `zy` 与参照实现的前缀无公共前缀，两份代码长期对照阅读不会混。
2. **CLI 命令名 `zy` 只有两字母 —— 这是简写形态的代价**。两字母命令名在系统 PATH 上与其他工具冲突的概率不低。**分发时以发行包名 `zy-agents` / npm scope `@zy-agents/cli` 为准，`zy` 是命令别名**；若实测冲突，用户可退回长名调用，契约标识不受影响。
3. **可做镜像名前缀与状态目录名** —— `zy-agents`、`zy` 全小写 ASCII、无空格、跨平台合法。
4. **无常见歧义** —— 不承担 `ap` 那类通用缩写（Application / Access Point / Accounts Payable）的歧义负担。

## 监督执行

`00` 中的硬约束已统一编号为 `S-nn`（共 **64** 条），登记在 `05-spec-compliance.md`。开工时按 `05` §4 的**阶段闸门**执行：进入某阶段前，该阶段对应的条款必须已全绿。

其中 **10 条**须人工把关——6 条 `REVIEW`（无自动化手段）+ 4 条结构性闸门 `GATE`，`05` §5 已逐条说明，不假装自动覆盖。

## 品牌与白标

产品以**单租户私有化**交付，展示层的品牌**每部署可配**（客户公司名 / logo / 主题色 / 文案），见 `00` **§12**。关键边界：客户品牌只作用于**展示层 + 模型请求的运行时上下文**，**绝不进入契约命名空间 / Profile 编译输入**——改品牌不使任何会话失效。厂商标识（`zy.*.v1` 等协议标识）**不可白标**。
